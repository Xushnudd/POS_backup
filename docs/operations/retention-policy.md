# Retention konfiguratsiyasi — ADR-062 core

Migration110 bazada dastlabki siyosatni yaratadi: obuna/trial davri tugagan sanadan 90 kunlik saqlash rejasi, yopish so‘rovini 30 kun ichida bekor qilish rejasi, moliyaviy hujjatlarning tegishli toifalari uchun 5 yillik biznes taklifi. Audit, texnik log va backup muddatlari NULL — hali tasdiqlanmagan. 5 yil barcha ma’lumotga tatbiq etilmaydi; huquqiy toifalar va o‘chirish majburiyatlari alohida tasdiqlanishi kerak. Bu hujjat huquqiy xulosa emas.

`GET /api/billing/retention`: faol owner yoki haqiqiy platforma administratori uchun reja. Oddiy admin/kassirga ruxsat yo‘q. Javob tashkilotning haqiqiy obunasi va bazadagi joriy policy versiondan hisoblanadi. Legacy tashkilotda davr tugashi/ko‘rib chiqish sanasi taxmin qilinmaydi. Trial/active/grace davomida plannedReviewAt=NULL; grace tugagach actual periodEndsAt+configured days olinadi. Obuna yangilansa sana yana joriy obunaga mos hisoblanadi. Sana yetganda reviewDue=true; hech narsa o‘chirilmaydi. GET sessiya idle muddatini uzaytirmaydi. Ichki policy reason/createdBy owner javobida berilmaydi.

`POST /api/billing/retention`: faol PlatformOperator.platform_admin va password sessiyasi majburiy. Body: operationId, expectedVersionId, expiredSubscriptionDays(1..3650), closureCancellationDays(1..365), auditRetentionDays/technicalLogRetentionDays/backupRetentionDays(NULL yoki1..3650), proposedFinancialRetentionYears(5..100), reason(3..2000). Destructive switch yoki noma’lum property rad etiladi.403 PLATFORM_ADMIN_REQUIRED,409 RETENTION_POLICY_CHANGED yoki OPERATION_PAYLOAD_CONFLICT,503 RETENTION_POLICY_UNAVAILABLE. Global advisory transaction lock, optimistic expectedVersion, immutable DB versiya, current pointer va audit bir tranzaksiyada. Original operation replay current operator vakolatini qayta tekshiradi. SQL guard unauthorized version author, tarix tahriri/o‘chirish va silent rollbackni rad qiladi.

`/billing`dagi saqlash paneli ownerga rejani ko‘rsatadi; faqat haqiqiy platforma administratoriga review/confirm form ko‘rinadi. Lost acknowledgmentdan keyin DurableMutation original key/body bilan qayta tekshiradi; yangi versiya takror yaratilmaydi. Tasdiqlanmagan nullable muddatlar UIga ochiq ko‘rsatiladi. Publish pointer satrini FOR UPDATE bilan qulflaydi: Serializable snapshot eskirgan bo‘lsa transaction retry qilinadi, keyin expectedVersion qayta tekshiriladi. Sakkiz parallel bir xil expectedVersion tahriri testi bir yangi versiya va yetti RETENTION_POLICY_CHANGED natijasini talab qiladi.

## Hali tugallanmagan BIZ-02.07 doirasi

Bu versiya avtomatik irreversible deletionni amalga oshirmaydi: API automaticDeletionEnabled=false va legalPolicyStatus=review_required. Migration111–112 bilan reviewed tenant biznes JSON eksporti va manifest mavjud: `docs/operations/tenant-export.md` doirani, chiqarilmagan credential/proof toifalarini va hajm chegaralarini tushuntiradi. Obuna grace tugagach business-write read-only SQL/operation guardlari mavjud: `docs/operations/subscription-read-only.md`. Owner reauthentication bilan organization close request/cancellation va closure lifecycle keyingi core scope. closureAvailable=false; mavjud bo‘lmagan yopish funksiyasi yoki huquqiy approval UI orqali va’da qilinmaydi.90/30 kun qiymatlari hozir saqlangan konfiguratsiya, yopish/o‘chirish ishlagani dalili emas. Expired obunada reviewed biznes yozuvlari read-only guard bilan himoyalangan; billing/auth/support/export va tor housekeeping istisnolari alohida contractda ko‘rsatilgan. Shu sababli BIZ-02.07 done emas.

Audit, technical logs, backup uchun ushbu yangi konfiguratsiya purge jobni avtomatik ishga tushirmaydi va avvalgi security-event 90 kun/minimal audit saqlash oqimini yashirin o‘zgartirmaydi. Shu qiymatlarni tegishli category workerga ulashdan oldin alohida siyosat/qabul testlari talab etiladi. Huquqiy toifalar va qaytarib bo‘lmaydigan o‘chirish blocked_external.
