# Operator scheduler namunalari — o‘rnatilmagan

Faqat systemd tanlangan Linux host uchun; boshqa hosting tanlansa shu scriptlarni uning scheduleriga ulang. `staging` va `production` instance bilan alohida `pos-ops-staging`/`pos-ops-production` service account, `/etc/pos/<instance>` root-owned private konfiguratsiya, `/var/lib/pos-backups/<instance>` va `/var/lib/pos-ops/<instance>`0700 kataloglarni operator yaratadi. `/opt/pos` release scriptlarining read-only operator joylashuvi; bu yo‘llar hozir mavjud deb hisoblanmaydi. Node24, PostgreSQL15 client va GPG operator tomonidan o‘rnatiladi va executable paths tekshiriladi.

`backup.env`0600: DATABASE_URL, BACKUP_DIRECTORY (instance katalogi), BACKUP_RECIPIENT (tasdiqlangan public recipient fingerprint), POS_BACKUP_APP_VERSION (haqiqiy image/release), POS_SECRET_RECOVERY_REFERENCE, GNUPGHOME (instance ops katalogidagi protected public keyring). Backup servicega decryption private key kerak emas. Host URL internal Compose hostname `db` bilan bir xil emas: operatorning private DB network accessi alohida tanlanadi; DB portini internetga ochmang. Private env fayllarini `source` yoki logga chop qilmang.

`monitoring.env`0600: POS_PROBE_ORIGIN — haqiqiy tasdiqlangan HTTPS origin. Uptime unit **ilovadan mustaqil hostda** bo‘lsa app/server outage kuzatiladi. Bir xil hostdagi timer mustaqil monitoring qabuli emas. `disk.env`: POS_DATA_DIRECTORY — aynan kerakli real data mount, POS_DISK_MIN_FREE_BYTES/PERCENT tasdiqlangan threshold. DB/export/backup turli mount bo‘lsa har biri uchun alohida disk instance va konfiguratsiya kerak.

Timer interval/daily02:00UTC faqat boshlang‘ich taklif, tasdiqlangan RPO/SLA emas. `systemd-analyze verify`ni actual units/path/account/environment bilan hostda bajaring; keyin individual service smoke, keyin egasining ruxsati bilan timer install/enable. Persistent daily backup host qaytganda missed runni bajaradi; xizmatning nonzero exit holati journaldga chiqadi. **Journald failure real on-call alert delivery emas**; provayder va mas’ul tanlangach nonzero/overdue/no-new-artifact monitoringini unga ulang.

Bu konfiguratsiya off-site nusxa yetkazish, secret backup schedule, otomatik restore yoki backup deletionni bajarmaydi. `backup-secrets.sh`ni alohida operator nazoratida key/config o‘zgarishida ishga tushiring. Restore destructive-gate/review/empty-target tartibi sabab faqat tasdiqlangan isolated rehearsalda bajariladi. RTO/RPO, backup retention/deletion va remote custody tasdiqlanmaguncha taxminiy SLA yoki avtomatik o‘chirish qo‘shilmadi.
